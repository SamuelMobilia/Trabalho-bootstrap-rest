Como usar os dados nas suas telas

Um pacote com 12 pesquisadores e 30 artigos, e um arquivo JavaScript que funciona como se fosse uma API. Dá para montar a tela inteira sem servidor e sem internet para os dados.

PASSO 1Os arquivos

O pacote vem organizado assim. Crie o seu HTML na raiz, ao lado das duas pastas:

sua-pasta/
  index.html          <- o seu arquivo
  js/
    dados.js          os dados
    gepiseg-api.js    o que você usa para buscar
  json/
    pesquisadores.json      os 12, numa lista só
    artigos.json            os 30, numa lista só
    pesquisador/1.json      cada um também sozinho
    artigo/1.json           …até o 30

Você só precisa dos dois arquivos de js/ para a tela funcionar. Os de json/ são para abrir e olhar como os dados são.

A url de um recurso é o caminho do arquivo dele. O artigo 7 tem "url": "json/artigo/7.json" — abra esse caminho no navegador e você vê exatamente o que api.artigos.porId(7) devolve.

Por isso a relação funciona com fetch puro

Como a referência é um caminho que existe, dá para seguir uma relação sem o cliente, só com o navegador: 

const artigo = await (await fetch('json/artigo/7.json')).json();
const autor  = await (await fetch(artigo.autorPrincipal.url)).json();

autor.nome;   // "Diego Albuquerque Rosa"

Isso precisa de servidor local (npx serve), porque o navegador bloqueia fetch de arquivo aberto com duplo clique. Com os scripts do passo seguinte, funciona sem servidor.

Por que separado em pastas?

Para ficar claro o que é código e o que é dado. É assim que um projeto de verdade se organiza, e evita uma pasta só com tudo misturado quando vocês forem somando CSS e imagens.

PASSO 2A primeira tela

Crie um index.html na raiz (ao lado das pastas js/ e json/) e cole isto:

<!doctype html>
<html lang="pt-BR">
<body>
  <div id="lista"></div>

  <script src="js/dados.js"></script>
  <script src="js/gepiseg-api.js"></script>
  <script>
    const api = GepisegAPI.criar();

    async function mostrar() {
      const r = await api.artigos.listar();

      for (const artigo of r.results) {
        document.getElementById('lista').innerHTML +=
          '<h2>' + artigo.titulo + '</h2>';
      }
    }

    mostrar();
  </script>
</body>
</html>

Dê duplo clique no arquivo. Devem aparecer os títulos dos artigos.

Deu erro "Dados não encontrados"?

Duas causas possíveis: o dados.js tem que vir antes do gepiseg-api.js, e os dois caminhos começam com js/. Confira as duas linhas.

r.info.pages     // quantas páginas
r.info.next      // "json/artigos.json?page=2", ou null se acabou
r.info.prev      // idem para a anterior, ou null se é a primeira

PASSO 4Buscar e filtrar

Passe um objeto com o que você quer. Pode combinar quantos quiser.

await api.artigos.listar({ q: 'phishing' });            // busca livre
await api.artigos.listar({ ano: 2025 });                // de um ano
await api.artigos.listar({ tema: 'IoT' });              // de um tema
await api.artigos.listar({ pesquisador: 1 });           // de uma pessoa
await api.artigos.listar({ ordenar: 'citacoes' });      // mais citados
await api.artigos.listar({ pagina: 2, porPagina: 6 });  // paginando

// combinando
await api.artigos.listar({ q: 'IoT', ano: 2025, ordenar: 'citacoes' });

PASSO 6Os autores de um artigo

O artigo não carrega o pesquisador inteiro dentro dele. Carrega o nome e o link — o suficiente para desenhar um card sem buscar mais nada. 

artigo.autores
// [ { nome: "Ana Clara Figueiredo", url: "json/pesquisador/1.json" }, ... ]

artigo.autorPrincipal
// { nome: "Ana Clara Figueiredo", url: "json/pesquisador/1.json" }

Do outro lado vale o mesmo: o pesquisador lista os artigos dele com título e link.

pessoa.artigos
// [ { titulo: "SSRF em arquiteturas de microsserviços...",
//     url: "json/artigo/2.json" }, ... ]

Dá para montar a página de perfil inteira — nome, bio, métricas e a lista de publicações — sem nenhuma busca extra.

Na tela de detalhe, quando você quiser a pessoa inteira (bio, áreas, métricas), siga o link:

const pessoa  = await api.seguir(artigo.autorPrincipal);
const pessoas = await api.seguir(artigo.pesquisadores);  // a lista toda

// vale nos dois sentidos
const trabalhos = await api.seguir(pessoa.artigos);

O seguir aceita tanto o objeto ({ nome, url }) quanto a URL solta, e aceita uma lista inteira de uma vez.

api.seguir(artigo.pesquisadores)

PASSO 7As fotos

O campo imagem carrega de verdade, tanto no artigo quanto no pesquisador:

<img src="${artigo.imagem}" alt="">
<img src="${pessoa.imagem}" alt="${pessoa.nome}">

A foto é sempre a mesma: cada registro tem uma fotoSeed fixa e a URL se monta a partir dela. Dar F5 não troca a imagem.

Sempre tenha um plano B para a imagem

As fotos vêm de um serviço de fora. Se a internet cair, você não quer um ícone de imagem quebrada na tela. Todo pesquisador tem iniciais e cor; todo artigo tem capa.cor: 

<img src="..." onerror="this.replaceWith(avatarDeIniciais(pessoa))">

// ou, mais simples: nem tenta a imagem
<div style="background: ${pessoa.cor}">${pessoa.iniciais}</div>

PASSO 8Os três erros que todo mundo comete

1. Achar que busca vazia devolve lista vazia

Não devolve: dá erro. Então o seu "nenhum resultado" mora no catch.

try {
  const r = await api.artigos.listar({ q: 'xyz' });
  mostrarLista(r.results);
} catch (e) {
  document.getElementById('lista').innerHTML = 'Nenhum artigo encontrado.';
}

Vale também para porId com um id que não existe.

api.artigos.listar({ q: 'xyz' })
carregando…

2. Esquecer o await

Toda chamada é assíncrona. Sem await você recebe uma Promise, não os dados — e a tela mostra [object Promise]. 

const r = api.artigos.listar();        // ERRADO
const r = await api.artigos.listar();  // certo

E a função que usa await precisa ser async:

async function mostrar() {
  const r = await api.artigos.listar();
}

3. Não mostrar que está carregando

Toda chamada demora 120 ms de propósito, para vocês praticarem isso. Escreva "carregando…" antes de chamar, e troque pelo conteúdo quando a resposta chegar. 

lista.innerHTML = 'carregando…';
const r = await api.artigos.listar();
lista.innerHTML = montarHtml(r.results);

Enquanto estiver depurando, pode desligar o atraso:

const api = GepisegAPI.criar({ atrasoMs: 0 });

  q, pesquisador, autorPrincipal,
  tema, veiculo, tipo, status, palavraChave,

  citacoesMinimas,
  ordenar,                   // recentes | antigos | citacoes | titulo

});

api.pesquisadores.listar({
  q, nome, area, titulacao, ativo,
  ordenar,                   // nome | artigos | citacoes
  pagina, porPagina
});

O formato das respostas segue o da Rick and Morty API (rickandmortyapi.com). Se um dia praticarem com outra API pública, vão encontrar o mesmo desenho: info + results, relação por link, erro com status 404. A diferença é que lá o link é uma URL completa (https://…/character/1) e aqui é o caminho do arquivo — porque aqui ele precisa abrir de verdade.

Os pesquisadores e artigos são fictícios, criados para o exercício. Não há perfil de rede social, Lattes nem ORCID nos dados: um endereço montado a partir de um nome inventado costuma cair no perfil de alguém de verdade. Os avatares são ilustrações geradas, não fotos de pessoas.
